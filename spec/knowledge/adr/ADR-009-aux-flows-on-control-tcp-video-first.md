# ADR-009：辅助流承载于控制 TCP 记录通道，积压时视频优先

date: 2026-11-10
status: accepted

## Context

M3 起系统需承载音频、剪贴板、文字输入等低带宽辅助流。可选承载方案有二：为辅助流新开独立传输面（新端口/新连接/新握手协商），或复用既有控制 TCP 记录通道。控制通道是 Framing 逐记录封装的可靠有序流（TCP/frp-TCP），AAC 96kbps 级音频远小于其带宽富余；但控制通道同时承载触摸回传与会话控制（并是视频的 TCP 回落路径），弱网下音频大流量可能积压并阻塞视频。音频丢帧比延迟更伤体验，而视频卡顿比音频延迟更不可接受——两者在弱网下冲突，需要明确优先级裁定。

## Decision

辅助通道一律复用控制 TCP 记录通道承载：不新开传输面、不新增端口、不引入握手协商字段，通道能力运行期探测、经回执/降级路径呈现。积压防护裁定视频优先：源端音频下行队列有界（满丢最旧），PING/PONG 看门狗监测控制通道积压，积压超阈值即丢弃积压音频保视频不阻塞；音频侧以客户端 jitter buffer 起播水位吸收抖动，skip 计数如实呈现丢弃。后续新增低带宽辅助通道沿同一承载模式扩展；高带宽或实时性要求与控制通道不匹配的流，需另行裁定承载面。

## Consequences

- 辅助通道零新增连接/端口/握手字段，老端按未知类型容错即兼容，协议版本不 bump。
- 音频可靠有序但与视频回落路径共享带宽：极端弱网下音频被整段丢弃保视频，音频断流先于视频劣化出现（产品语义：视频优先）。
- 控制通道带宽预算从此包含 96kbps 级音频，后续通道扩展需持续评估控制通道容量。
