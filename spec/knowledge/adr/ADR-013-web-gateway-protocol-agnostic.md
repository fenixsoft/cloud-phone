# ADR-013：Web 观看面网关协议无关，浏览器端 TS 逐字节复刻协议

date: 2026-11-12
status: accepted

## Context

浏览器作为第三观看端形态接入云手机串流时面临两个结构性约束。其一，浏览器无法像 Windows 客户端那样经复合构建消费 Kotlin protocol 模块（ADR-011 的路径对浏览器不可用），协议语义必须有浏览器侧的承载方式。其二，宿主机上需要一个新的常驻接入层（浏览器只会说 WebSocket）；若让网关理解协议，协议语义就要写两遍，并随每次协议演进而双改，网关从此被协议绑定。

## Decision

网关被裁定为**协议无关的 WS↔TCP 纯字节中继**：双向逐字节搬运带背压，同端口托管浏览器静态页与 `/ws` 升级，永不解析、改写、过滤任何消息，认证/会话/错误一律由源端协议层裁决。协议的唯一实现留在端侧：浏览器端以 TypeScript 逐字节复刻 docs/protocol.md，golden 向量从 Kotlin 测试用例与真机实际字节导出、双向断言逐字节一致，解码器对未知尾部字节容忍跳过；源端、protocol、既有客户端工程零改动。未来演进路线 B（WebRTC）时网关原地升级为信令 + RTP 端点，浏览器协议层/输入层代码保留复用。

## Consequences

协议语义在 TS 侧存在第二份实现，漂移风险由 golden 向量测试兜底——协议每次变更必须同步更新 golden 向量与 TS 编解码，否则浏览器端停留在旧协议。网关因零协议知识而永不随协议演进改动，但也因此不具备协议级路由与鉴权能力：v1 明文直通、token 即唯一凭据，保密性与 frp 通道同级，HTTPS 需在外层（frp/nginx）终结。
