## ADDED Requirements

### Requirement: 局域网源端自动发现

客户端连接首页 SHALL 在进入时自动扫描设备所在局域网子网，对候选地址的 TCP 22333 端口发起探测（连接握手即可判定服务存在，不要求完成 A2A 配对），并在界面上完整呈现「扫描中 → 有发现 / 未发现」三态。扫描 MUST 支持手动重试；探测 MUST 在后台线程执行，不阻塞 UI；重复地址 MUST 去重；单个地址探测超时 MUST NOT 拖慢整体扫描完成（总时长上限 ≤10s）。发现卡片的传输后端标识按 host+port 匹配既有档案显示其后端；未匹配档案的新发现源端显示默认 lan-direct 标识——探测不握手，MUST NOT 将探测结果用作真实传输后端的判定。

#### Scenario: 进入首页自动扫描并发现源端
- **WHEN** 用户进入连接首页且所在局域网存在监听 TCP 22333 的源端（如 192.168.1.23）
- **THEN** 界面先显示扫描中状态（含进度反馈），扫描完成后「局域网源端」区块列出该源端卡片，卡片含名称、在线状态徽章、地址（IP:22333）、传输后端标识、上次连接信息

#### Scenario: 扫描中状态与重试
- **WHEN** 扫描正在进行
- **THEN** 界面显示扫描中状态（探测进度计数），用户可点击重试重新触发扫描

#### Scenario: 无响应源端呈现
- **WHEN** 子网内某地址曾保存过档案但本次探测 22333 无响应
- **THEN** 该源端卡片以「无响应」状态呈现（视觉弱化、连接按钮置为不可达禁用态），不参与可连接列表

### Requirement: 连接首页信息架构

连接首页 SHALL 自上而下呈现：顶栏（标题、设置入口、会话抽屉入口）、网络状态徽章、扫描面板、发现的源端卡片列表、手动保存的连接档案卡片列表、常驻「新建连接」入口。在线源端卡片 MUST 提供两个动作：连接（进入控制台）、单应用（直接进入该源端应用列表）。档案卡片 MUST 提供连接与删除动作（探测无响应的档案卡连接动作置为禁用态，见「局域网源端自动发现」；删除动作始终可用）。

#### Scenario: 首页完整结构
- **WHEN** 扫描完成且存在已保存档案
- **THEN** 首页依次可见：顶栏（含设置入口）、扫描结果区块（发现 N 台）、手动保存的连接区块（N 个档案）、新建连接入口

#### Scenario: 从卡片一键连接
- **WHEN** 用户点击在线源端卡片或档案卡片上的「连接」
- **THEN** 客户端以该卡片的地址/端口/后端/token 发起连接（档案无 token 时进入连接流程按既有规则处理），成功后进入控制台

#### Scenario: 从卡片直达单应用列表
- **WHEN** 用户点击在线源端卡片上的「单应用」
- **THEN** 客户端建立连接后直接进入该源端的应用列表页

### Requirement: 手动新建连接

未发现源端时（公网/热点/源端未开机），首页 SHALL 显示空态引导（说明可能原因 + 「手动新建连接」与「重试扫描」两个动作），且常驻新建入口在任何状态下均可用。新建连接 SHALL 以底部弹层表单呈现，字段与布局 MUST 为：连接名称（可选）、主机地址/IP（独占一行）、TCP 端口与 UDP 端口（同行并排，默认 22333/22334）、传输后端三选一（lan-direct/p2p/frp，默认 lan-direct）、配对 token（密码态输入）、高级选项折叠区（分辨率/帧率/码率/观看模式，默认「跟随本机」/60/8 Mbps/整屏镜像）。保存 MUST 校验主机地址非空，成功后档案卡片实时追加到首页列表并可立即连接；保存的档案 MUST 复用 source-profiles 既有持久化存储。

#### Scenario: 未发现空态引导
- **WHEN** 扫描完成且未发现任何源端
- **THEN** 首页显示空态（原因说明 + 手动新建连接 + 重试扫描），手动保存区块与新建入口仍然可用

#### Scenario: 手动保存档案并回显
- **WHEN** 用户在新建连接表单填入地址 10.8.0.5、名称「测试云机」并保存
- **THEN** 表单关闭并 toast 确认，首页档案列表实时追加「测试云机」卡片（地址 10.8.0.5:22333、所选后端徽章、token 状态、保存时间），该卡片可一键连接、可删除，且重启客户端后仍存在

#### Scenario: 表单字段布局与默认值
- **WHEN** 用户打开发新建连接表单
- **THEN** 主机地址独占一行，TCP/UDP 端口同行并排且预填 22333/22334，传输后端默认选中 lan-direct，高级选项默认折叠；地址为空提交时给出「请填写主机地址」提示且不保存

#### Scenario: 删除档案
- **WHEN** 用户删除某个手动保存的档案卡片
- **THEN** 该卡片从列表移除、持久化存储同步删除、计数更新

### Requirement: 控制台（系统画面）

连接成功后 SHALL 进入全幅画面控制台，画面区呈现源端系统镜像（复用既有解码渲染管线）。控制台 MUST 包含：顶部 HUD 统计条（FPS/码率/RTT/丢包复用既有 STATS 统计上报；分辨率读数取解码输出 MediaFormat 实际值——STATS 消息无分辨率字段；间隔刷新）、底部工具坞（键盘唤起、截屏、串流档位循环切换、旋转（本地切换客户端横竖屏呈现，MUST NOT 改源端）、单应用入口、断开）、Android 虚拟导航键（BACK 经既有 INPUT_EVENT InputAction.BACK 注入源端；HOME/RECENTS 协议无对应消息，本期预留占位，MUST NOT 为其扩展协议或改源端）、会话抽屉（从画面边缘唤出，含挂起/恢复与断开）。档位切换 MUST 遵循既有 resolution-passthrough 参数语义发起：以新档位参数重发整屏 START_SESSION（控制链路保持不断开），源端按新参数重建采集/编码管线后经 IDR 秒回恢复画面——既有语义为「同一会话内不改参数」，MUST NOT 表述或实现为同会话内原地改参。

#### Scenario: 控制台完整元素
- **WHEN** 连接成功进入控制台
- **THEN** 画面全幅呈现源端系统画面，顶部 HUD 显示 FPS/码率/RTT/丢包/分辨率实时值，底部可见工具坞与虚拟导航键

#### Scenario: 工具坞档位切换
- **WHEN** 用户在工具坞点击档位切换
- **THEN** 档位按 1080P·60 → 720P·60 → 1080P·30 → 自定义 顺序循环，HUD 分辨率读数随源端实际输出更新，控制连接保持不中断（画面经管线重建短暂停顿后恢复）

#### Scenario: 虚拟导航键注入
- **WHEN** 用户点击控制台虚拟导航键 BACK
- **THEN** 客户端经触控回传通道向源端注入 BACK 键事件，源端画面相应变化

#### Scenario: 截屏
- **WHEN** 用户点击工具坞截屏
- **THEN** 当前画面保存到客户端本地（toast 确认），会话不中断

#### Scenario: 会话挂起与恢复
- **WHEN** 用户在会话抽屉选择挂起
- **THEN** 会话进入挂起态（画面停更、状态标注挂起），选择恢复后会话恢复出帧；断开则回到连接首页

### Requirement: 单应用列表与单应用画面

控制台 SHALL 提供「单应用」入口进入应用列表页：应用以磁贴网格呈现，每磁贴仅含应用图标（通用占位即可）与应用名称（深色底上白色文字），MUST NOT 显示包名；搜索框按应用名称过滤；每磁贴右上角图钉可创建桌面快捷方式（复用既有 app-shortcuts 能力，直达 cloudphone://launch 单应用）。点选磁贴 SHALL 打开单应用画面（虚拟屏单应用会话），顶部显示「单应用 · <应用名>」模式徽章，徽章提供一键退出返回系统画面。

#### Scenario: 应用列表磁贴
- **WHEN** 用户从控制台进入单应用列表
- **THEN** 应用以图标+名称磁贴网格呈现（无包名行），名称为白色文字，搜索框输入「原神」时列表实时过滤只剩匹配磁贴

#### Scenario: 打开单应用
- **WHEN** 用户点选某应用磁贴
- **THEN** 进入单应用画面，顶部显示「单应用 · <应用名>」徽章，画面区呈现该应用内容

#### Scenario: 退出单应用
- **WHEN** 用户点击模式徽章上的退出
- **THEN** 单应用会话结束，返回系统画面控制台，会话保持

#### Scenario: 加到桌面
- **WHEN** 用户点击磁贴右上角图钉
- **THEN** 按既有 app-shortcuts 能力创建桌面快捷方式（请求 pin），确认后桌面图标可直达该应用单应用会话

### Requirement: 设置页（预留）

首页顶栏 SHALL 提供设置入口，进入独立设置页。设置页 MUST 含分组：外观（主题/深色模式开关，MVP 允许占位）、串流档位默认值（分辨率/帧率/码率）、传输偏好（默认端口 22333 展示与修改）、触控输入（触控灵敏度等占位）、安全（预留，标注「预留」徽章）、关于（版本号、检查更新）。未实现项 MUST 显式标注「预留」，不得伪装为可用功能。设置项变更 MUST 持久化并在下次会话生效（涉及会话中的项于下次连接生效）。

#### Scenario: 设置页结构与预留标注
- **WHEN** 用户从首页顶栏进入设置
- **THEN** 设置页呈现外观/串流档位/传输偏好/触控输入/安全/关于六个分组，未实现行带「预留」标注且不可产生实际效果

#### Scenario: 默认档位持久化
- **WHEN** 用户在设置中修改串流档位默认值并返回
- **THEN** 该值持久化，下次新建连接表单的高级选项默认值随之变化
